# Walking the game on the Raspberry Pi

These play the game with no screen attached, for measuring frame rates at 1080p. They run from `test/` in the checkout on the Pi, `~/wii-recomp` unless `WII_RECOMP_DIR` says otherwise, next to the build in `recomp/build`.

- `walk2.sh <seconds> <script>` starts a headless labwc and the game, then sends the script's commands to the control pipe at their times. A line is `<second> <command>`, where the command is anything the pipe takes (`press a`, `pointer x y`, `board on kg x y`, `board off`), `shot <name>` for a screenshot, or `react` to hand over to `react.py`. It prints the frame rates it saw. It plays `games/RFPE01.wrd`, the image `add_game.py` makes, or `WII_RECOMP_GAME` (`extracted/sys` for the native code built beside the console), with no attachment on the remote so Wii Fit shows its pointer.
- The scripts' pointer positions are for builds where the game's own Wii Remote code reads the simulated camera, as `add_game.py` builds. A game built without `--virtual-bluetooth` is handed the pointer directly, and Wii Fit draws that 0.12 of the screen lower and 10% narrower; `WALK_POINTER=direct` converts the positions for it (x × 1.11, y − 0.127).
- On the game's own Wii Remote code, the walk gets through the Mii and to the board's setup, where the game drops the simulated board and asks for its power button, so the Body Test is walked on a direct-input build for now: `sh test/run.sh <name> 780 WII_RECOMP_GAME=extracted/sys WALK_POINTER=direct`, with that build beside the console.
- `w20.txt` creates a Mii and gets to the board's setup, then reacts from there.
- `mii.txt` stops on the Mii page at 1080p's slowest steady screen; a 68-second walk is enough, with a screenshot `w-m.png` at 60 seconds.
- `run.sh <name> <seconds> [VAR=value ...]` runs a walk (`SCRIPT=mii.txt` for the Mii page) and writes `test/<name>.out` with the seconds spent at each frame rate and any warnings. Add `WII_RECOMP_GPU_TIMES=1` for what the chip spent on each pass. Start it with `setsid`, as Wi-Fi on the Pi can drop under load.
- `react.py` watches the dialog box and answers like a person: it steps on when asked, steps off and presses A when the game wants it off, and clicks the right button on screens where A alone does nothing. Anything else gets A every 6 seconds; if an unknown screen stops changing for 15 seconds, it clicks the usual button spots in turn (Next and OK at the bottom right, the middle, the bottom left). On the calendar it aims the stamp at today's square, found by its pale yellow. With these it gets through the whole first-time setup to the safety warning before the main menu. Screens it doesn't know are saved once as `u-NN.png`, and its decisions go to `react.log`.

`react.py` recognizes screens by comparing the dialog box with images in `ref/`, cut from screenshots at (60, 186, 560, 240) of a 640x360 shot. Those are pictures of the game, so they stay on the Pi and aren't in this repo. Make them from a run's `u-NN.png` files and name each one after what the script should do: `stepon`, `stepoff`, `cantfind`, `reboot` or `clothing`.

A walk to the end of the Body Test takes about 13 minutes: `sh walk2.sh 780 w20.txt`.
